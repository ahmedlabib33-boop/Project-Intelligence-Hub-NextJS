# Generic Reuse Prompt — Any Other Project

Use the prompt below when applying this package to a different project.

---

Create a new project instance using the four-pipeline methodology contained in this package.

New project name: `[ENTER PROJECT NAME]`  
New project ID: `[ENTER UNIQUE PROJECT ID]`

Start with empty project-specific registers. Do not copy any facts, dates, quantities, parties, events, clauses, amendments, schedule results, risk allocation, EOT values, evidence status or conclusions from **ROYA-BIG PROJECT PHASE01 (B1-4)** or any other project.

Reuse only:

- Four-pipeline architecture
- Analytical methodology
- Evidence classifications
- Validation rules
- Output schemas
- Report templates
- UI components
- Generic clause-routing concepts that are revalidated against the new signed Contract

Then:

1. Inventory the new project's sources.
2. Build its signed contractual hierarchy.
3. Index its authorized Contract and FIDIC sources.
4. Create its evidence and chronology registers.
5. Validate and analyze its native schedules.
6. Assess each event through contractual, evidential and schedule gates.
7. Generate the Master Assessment and validated visuals.
8. Report missing evidence and limitations.
9. Run cross-project isolation tests before release.

No project conclusion may be generated until the new project's own sources support it.
